# 开发计划与验收门槛 v0.4

项目：`ziyuuu/return-old-school`  
版本日期：2026-09-09

## 1. 项目定位

`return-old-school` 首先是一个 **雅礼中学东塘校区的校园数字复原项目**，其次才是一个恐怖解谜游戏。

项目用途是校庆与校友体验，不按商业游戏立项。当前评价标准不是“玩法有多少”“流程有多长”，而是：

1. 校友进入场景后，能否迅速认出自己熟悉的校园；
2. 建筑、道路、运动区、室内连接关系是否经得起照片与校友记忆校核；
3. 近距离观察时，模型是否仍然可信，而不是只在远景截图中成立；
4. 白天与夜晚是否都建立在同一套可信校园资产上；
5. 后续剧情与游戏内容不得反过来破坏已经确认的校园事实。

**项目优先级：真实校园复原 > 模型精度与环境完整度 > 白天现代校园表现 > 夜间中式梦核表现 > 剧情与具体玩法。**

当前阶段暂不设计具体谜题、怪物 AI、战斗、追逐、道具经济或流程长度。

---

## 2. 时间层与资产原则

项目需要同时处理两种校园状态，但二者不得混在同一份“历史事实”里：

- **2006—2010 历史基底**：作为校友记忆与校园复原的核心依据；建筑形体、连通关系、设施位置优先按同期资料和校友校正建立。
- **现代白天覆盖层**：用于“多年后返校”的白天场景。只记录已确认的改造、标识、设备和表面变化，不用现代照片反推当年状态。
- **夜间梦核覆盖层**：建立在已经通过校核的校园模型之上，以灯光、材质、声音、可逆的场景变体和有限空间异常形成中式梦核氛围。不得修改历史基底资产本身。

推荐资产结构：

```text
campus-base/            # 已校核的空间与建筑基底
layers/2006-2010/       # 历史时代特征
layers/present-day/     # 现代白天覆盖层
layers/night-dreamcore/ # 夜间梦核覆盖层
references/             # 照片、网页来源、校友批注、平面图
qa/                     # 对照机位、差分图、浏览器截图、验收记录
```

## 3. M0：证据基线与总平面锁定

M0 不追求模型完成度，而是为 M1 提供不会反复推倒重来的空间基准。

### 核心交付

- 2006—2010 目标年代资料索引；
- 现代校园照片索引；
- 原平面图的增量修订版；
- 所有已知设施编号与名称；
- 建筑之间的相对位置、朝向、连通关系、高差关系；
- “已证实 / 校友确认 / 高概率推定 / 待确认”四级证据状态；
- 每个关键建筑至少一组可复现的参考机位；
- 冲突资料登记，不强行统一不同年代状态。

### 当前必须保持的空间约束

- 独栋厕所位于原平面图图面左侧，并与主教学楼直接连接；
- 篮球场为 **3×2 六片**；球场长轴与相邻跑道方向平行；
- 音乐教室位于跑道边，同时位于体育馆后方；
- 篮球场 / 泳池区域厕所位于原平面图中游泳池左侧；
- 操场主席台位于操场图面左侧；
- 国旗附近存在沙坑；
- 校门右侧存在校名石；
- 体育馆必须以实拍中的折面体量、退窗、平台、入口和外梯为形体校核基准。

### M0 退出条件

- 平面图不再存在左右镜像、设施数量或关键连通关系错误；
- 未确认项目均明确挂牌，不用常见学校布局填空；
- M1 所需建筑清单、参考图和机位清单齐备。

# 4. M1：全场景深度还原与模型精度优化

**M1 是当前项目的绝对主阶段。** 其目标不是“做一条可玩路线”，而是先把整个校园做成值得校友反复观看、核对和漫游的数字空间。

## 4.1 M1 核心目标

1. 完成全校园室外空间的连续建模；
2. 完成所有主要建筑的高精度外观；
3. 完成有资料支撑、且对校友记忆重要的主要室内空间；
4. 对关键地标做近景级细化；
5. 让同一建筑在正面、侧面、背面、俯视和行走视角下都成立；
6. 建立 2006—2010 历史基底，并为现代白天覆盖层保留结构；
7. 在浏览器中达到可持续漫游的性能水平。

## 4.2 全场景范围

M1 以“校园完整度”组织，而不是以剧情章节组织。至少覆盖：

- 校门、门卫区、校名石、主入口道路；
- 主教学楼、北教学楼、南教学楼及其连廊；
- 主教学楼左侧相连的独栋厕所；
- 办公楼、实验楼、科学馆、图书馆；
- 体育馆完整外观与主要室内空间；
- 体育馆后方、跑道边的音乐教室；
- 食堂及主要就餐空间；
- 田径场、主席台、国旗区、沙坑、风雨跑道；
- 3×2 六片篮球场；
- 游泳池及其左侧厕所；
- 宿舍及其他有充分资料的校园建筑；
- 围墙、道路、台阶、坡道、排水、栏杆、树池、路灯、公告栏等环境构件；
- 具有时代辨识度的门窗、空调外机、管线、灯具、桌椅、黑板、标牌等细节。

资料不足的室内空间可以暂时关闭，但不得用无依据的“标准教室 / 标准厕所 / 标准办公室”冒充真实复原。

## 4.3 模型精度标准

### A. 空间精度

- 全项目统一真实单位，建议 `1 unit = 1 m`；
- 每栋建筑记录尺寸来源：实测、公开图纸、照片推算或校友确认；
- 不对缺失尺寸制造伪精确数值；
- 建筑位置、高差、入口、楼梯、连廊和厕所连接优先于表面装饰。

### B. 建筑形体精度

关键建筑需要通过至少三类视角校核：

- 正 / 斜前方；
- 侧面或背面；
- 校园步行视角或高位关系视角。

不能依靠一个“最像照片”的固定机位掩盖错误结构。

### C. 近景细节

对于校门、体育馆、主教学楼入口、教室、走廊、食堂等高频记忆场景：

- 门窗有真实进深；
- 柱、雨棚、窗台、女儿墙、栏杆、台阶不使用贴片假结构替代；
- 标识、题字和校徽位置按照片校准；
- 材质应表现瓷砖、混凝土、旧墙漆、玻璃、金属、木材等实际表面差异；
- 重复构件允许实例化，但不能因此丢失建筑特征。

## 4.4 体育馆专项

体育馆列为 M1 的重点资产，继续从当前工作模型提升到可近距离观察的建筑级模型。

必须进一步完善：

- 两侧折面壳体的厚度与真实交接；
- 中央立面的深浅层级；
- 五环所在正面体块比例；
- 内凹窗带、框架、玻璃进深；
- 首层平台、檐口、台阶与入口；
- 左侧外梯与主体的实际连接；
- 背面及侧后方体量；
- 室外壳体与室内篮球馆开口、楼层关系一致；
- 近景材质接缝、旧化和建筑节点。

验收必须提供同一模型至少 6 个固定机位截图，与照片逐一对照。

## 4.5 环境还原

“像学校”不能只靠建筑。M1 必须同步建立：

- 主要树木位置与树冠尺度；
- 校园边界、相邻住宅和可见城市背景的轮廓；
- 电线、灯杆、围墙、宣传栏、垃圾桶、消防设施等生活构件；
- 操场、篮球场、泳池、跑道的真实铺装和线位；
- 教室、走廊、食堂等空间中可辨认的日常陈设。

## 4.6 M1 技术目标

M1 的技术开发只服务于“看得准、走得动、便于校核”，不提前扩张玩法系统。

需要：

- 稳定的 Web 3D 场景加载；
- 第一人称或自由漫游查看；
- 固定对照机位；
- 区域分块 / LOD / 实例化；
- 模型坐标与设施 ID 保持稳定；
- 白天灯光基础；
- 一键输出校核截图；
- 能在常见电脑浏览器中持续运行。

可以暂缓：复杂交互、怪物 AI、谜题、任务、背包、剧情状态机、战斗与商业化 UI。

## 4.7 M1 验收标准

M1 完成不是“所有模型都存在”，而是同时满足：

- 校园室外空间可连续漫游，不出现明显空洞或临时盒子；
- 关键建筑全部完成多机位照片校核；
- 校友能凭空间关系辨认路线，而不依赖 UI 地图；
- 体育馆、校门、主教学楼、运动区等核心地标达到近景展示质量；
- 已开放室内从室外进入时拓扑、楼层和开口一致；
- 所有不确定结构在资产元数据中保留证据等级；
- 历史基底不被现代覆盖层或夜间效果污染。

# 5. M2：全校园夜间中式梦核设计

M2 在 M1 基础上进行。**M2 的重点是夜间世界的美术、空间与氛围设计，不是具体玩法设计。**

白天依然保持可信、正常、可怀旧的现代返校感；夜晚则让同一所学校进入循环梦境中的中式梦核状态。

## 5.1 核心原则

- 夜晚必须仍然能被校友认出是雅礼，而不是换成一个泛用恐怖学校；
- 恐怖来自“熟悉空间的不正常”，不是大量血迹、尸体或商业恐怖模板；
- 保留中国高中独有的视觉和声音记忆：走廊日光灯、广播、黑板字、塑钢窗、瓷砖、吊扇、食堂灯箱、操场扩音、晚自习灯光等；
- 梦核空间异常必须建立为覆盖层，能够随时恢复 M1 的真实校园基底；
- 夜间不依照现实钟表自动到来，具体触发规则留到后续游戏设计阶段。

## 5.2 M2 交付

### 全校园夜间视觉圣经

为每个主要区域定义：

- 主色与冷暖关系；
- 人工照明类型；
- 黑暗层级；
- 雾、空气感和可见距离；
- 反射、潮湿、灰尘等表面状态；
- 正常物件如何产生轻微错位；
- 哪些元素允许超现实变化，哪些历史结构绝不修改。

### 全场景夜间版本

至少为 M1 的所有核心区域建立可浏览夜间版本：

- 校门与校名石；
- 主教学楼、连廊与左侧厕所；
- 体育馆与音乐教室；
- 操场、主席台、国旗、沙坑、跑道；
- 六片篮球场、泳池与池左厕所；
- 食堂；
- 图书馆、实验 / 科学区域；
- 主要教室、楼梯间、走廊及宿舍公共区域。

### 声音氛围原型

只做环境氛围，不设计解谜机制：

- 远近广播；
- 风扇、电流、日光灯镇流器；
- 空体育馆回声；
- 运动场远处球声；
- 食堂设备低频；
- 宿舍、厕所与走廊的空间混响；
- 远处城市与校园内部声音的反差。

## 5.3 梦核空间语言

M2 可以实验但必须可逆的异常包括：

- 同一路段的长度在不同观察方向略有变化；
- 远端灯光比实际空间多一组；
- 一扇已知窗户后的室内亮着不属于当前楼层的灯；
- 校园广播声源方向和可见喇叭位置不一致；
- 同一张公告在不同区域出现，但纸面细节不同；
- 操场、体育馆、教室等大空间出现尺度感错觉。

这些仅作为视觉 / 空间研究方向；是否成为玩法规则，留待 M3 以后决定。

## 5.4 M2 验收标准

- 所有核心场景都有白天 / 夜晚成对截图；
- 夜间仍能凭建筑轮廓识别具体校园位置；
- 不依赖生成式图片假装实机效果；验收图必须来自实际 Web 3D 场景；
- 夜间变体不修改 M1 校准过的基底网格和设施坐标；
- 至少邀请一组校友只看场景、不讲剧情，确认“既熟悉又不安”的方向成立；
- M2 完成后才决定哪些空间异常转化为正式游戏机制。

# 6. M3 以后：互动与游戏内容（暂缓详细设计）

M3 以后才开始把校园复原和夜间梦核转化为完整游戏。

现阶段只保留高层级目标，不提前冻结具体玩法：

- 基础行走、查看与简单物件交互；
- 白天 / 夜晚的条件式切换；
- 循环梦境的存档和状态结构；
- 剧情、幽魂、怪物和谜题逐步加入；
- 最终整理成适合校庆期间分享给同学的浏览器版本。

M3 的设计必须服从 M1/M2 已完成的校园资产，而不是为了关卡便利随意挪门、改楼梯、堵道路或改变真实建筑比例。

## 7. 近期工作排序

当前所有工作重新排序如下：

### P0：校园空间与证据

- 完成修订总平面继续校核；
- 获取更多 2006—2010 校园照片；
- 为每栋楼建立证据卡；
- 校核厕所、音乐教室、体育馆后场、泳池周边等剩余模糊区域；
- 收集可用于尺度推算的门、窗、跑道、球场等已知尺寸参照。

### P1：全校园精模

- 将当前工作模型逐栋升级；
- 优先体育馆、校门、主教学楼、运动区；
- 随后完成食堂、教学楼群、实验 / 科学 / 图书区域、宿舍；
- 统一树木、铺装、围墙、道路、路灯与生活设施；
- 建立关键室内。

### P2：现代白天状态

- 根据可靠现代照片建立覆盖层；
- 不覆盖历史基底；
- 建立自然日光与普通校园生活感；
- 制作全部主要区域的现代白天对照截图。

### P3：中式梦核夜晚

- 等 M1 达到完整度后再系统展开；
- 同一模型制作夜间灯光、材质、声音和空间变体；
- 建立全校园夜间视觉圣经与对照机位。

### P4：具体游戏设计

暂缓。M1 与 M2 未通过验收前，不把团队时间投入谜题数量、怪物行为树、关卡时长或结局分支。

## 8. 面向校庆的发布标准

本项目不是商业产品，因此发布标准强调：

- 校友辨识度和回忆价值；
- 浏览器打开即可体验；
- 不需要账号、付费、商业后端或复杂运营系统；
- 资料来源和摄影权利尽可能清楚；
- 对真实师生保持尊重，虚构恐怖内容与真实校史明确区分；
- 即使后续游戏内容尚未完成，M1 的校园漫游版本本身也应能作为独立校庆作品发布。

**项目成功的第一判据不是“做成一个恐怖游戏”，而是“把那所学校重新做出来”。**
