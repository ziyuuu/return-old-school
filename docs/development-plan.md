# 开发计划与验收门槛 v0.5

项目：`ziyuuu/return-old-school`  
版本日期：2026-09-09

## 1. 项目定位

`return-old-school` 首先是一个 **雅礼中学东塘校区的校园数字复原项目**，其次才是一个恐怖解谜游戏。

项目用途是校庆与校友体验，不按商业游戏立项。当前评价标准不是“玩法有多少”“流程有多长”，而是：

1. 校友进入场景后，能否迅速认出自己熟悉的校园；
2. 建筑、道路、运动区、室内连接关系是否经得起照片与校友记忆校核；
3. 近距离观察时，模型是否仍然可信，而不是只在远景截图中成立；
4. 白天与夜晚是否都建立在同一套可信校园资产上；
5. 后续剧情与游戏内容不得反过来破坏已经确认的校园事实。

**项目优先级：真实校园复原 > 模型精度与环境完整度 > 白天现代校园表现 > 夜间中式梦核表现 > 剧情与具体玩法。**

当前阶段暂不设计具体谜题、怪物 AI、战斗、追逐、道具经济或流程长度。

---

## 2. 时间层与资产原则

- **2006—2010 历史基底**：作为校友记忆与校园复原的核心依据；建筑形体、连通关系、设施位置优先按同期资料和校友校正建立。
- **现代白天覆盖层**：用于“多年后返校”的白天场景。只记录已确认的改造、标识、设备和表面变化，不用现代照片反推当年状态。
- **夜间梦核覆盖层**：建立在已经通过校核的校园模型之上，以灯光、材质、声音、可逆的场景变体和有限空间异常形成中式梦核氛围。不得修改历史基底资产本身。

推荐资产结构：

```text
campus-base/            # 已校核的空间与建筑基底
layers/2006-2010/       # 历史时代特征
layers/present-day/     # 现代白天覆盖层
layers/night-dreamcore/ # 夜间梦核覆盖层
references/             # 照片、网页来源、校友批注、平面图
qa/                     # 对照机位、差分图、浏览器截图、验收记录
data/                   # 设施与空间硬约束
```

空间硬约束的机器可读版本见 [`../data/spatial-constraints.json`](../data/spatial-constraints.json)。

## 3. M0：证据基线与总平面锁定

M0 不追求模型完成度，而是为 M1 提供不会反复推倒重来的空间基准。

### 核心交付

- 2006—2010 目标年代资料索引；
- 现代校园照片索引；
- 原平面图的增量修订版；
- 所有已知设施编号与名称；
- 建筑之间的相对位置、朝向、连通关系、高差关系；
- “已证实 / 校友确认 / 高概率推定 / 待确认”四级证据状态；
- 每个关键建筑至少一组可复现的参考机位；
- 冲突资料登记，不强行统一不同年代状态。

### 当前必须保持的空间约束

- 独栋厕所位于原平面图图面左侧，并与主教学楼直接连接；
- 篮球场为 **3×2 六片**；
- **六片篮球场与相邻跑道方向平行，并且边界紧贴、直接相邻**；两者之间不得插入道路、绿化带、广场或无关建筑；
- **相邻跑道图面左侧存在一组体育辅助用房**，已知功能包括健身／锻炼空间、体育教师办公室、运动器材／器械存放空间；
- 体育辅助用房的精确分间、门窗、长度、进深和正式历史名称尚待核实，现阶段不能用常见学校布局补齐；
- 音乐教室位于跑道边，同时位于体育馆后方；**音乐教室与体育辅助用房是两个独立对象，不得合并**；
- 篮球场 / 泳池区域厕所位于原平面图中游泳池左侧；
- 操场主席台位于操场图面左侧；
- 国旗附近存在沙坑；
- 校门右侧存在校名石；
- 体育馆必须以实拍中的折面体量、退窗、平台、入口和外梯为形体校核基准。

### 运动区拓扑验收

在进入 M1 前，运动区总平面至少必须同时满足：

1. 六片篮球场数量和 3×2 排列正确；
2. 篮球场整体与相邻跑道平行；
3. 篮球场整体与相邻跑道紧贴；
4. 跑道图面左侧恢复体育辅助用房；
5. 体育辅助用房记录健身／锻炼、体育教师办公室、运动器材三个已知功能；
6. 音乐教室仍满足“跑道边＋体育馆后方”，并与体育辅助用房分开；
7. 未确认房间边界和尺寸使用虚线／待核标签，不制造精确值。

详细修订说明见 [`spatial-corrections.md`](spatial-corrections.md)。

### M0 退出条件

- 平面图不再存在左右镜像、设施数量或关键连通关系错误；
- 运动区通过上述拓扑验收；
- 未确认项目均明确挂牌，不用常见学校布局填空；
- M1 所需建筑清单、参考图和机位清单齐备。

# 4. M1：全场景深度还原与模型精度优化

**M1 是当前项目的绝对主阶段。** 其目标不是“做一条可玩路线”，而是先把整个校园做成值得校友反复观看、核对和漫游的数字空间。

## 4.1 M1 核心目标

1. 完成全校园室外空间的连续建模；
2. 完成所有主要建筑的高精度外观；
3. 完成有资料支撑、且对校友记忆重要的主要室内空间；
4. 对关键地标做近景级细化；
5. 让同一建筑在正面、侧面、背面、俯视和行走视角下都成立；
6. 建立 2006—2010 历史基底，并为现代白天覆盖层保留结构；
7. 在浏览器中达到可持续漫游的性能水平。

## 4.2 全场景范围

M1 以“校园完整度”组织，而不是以剧情章节组织。至少覆盖：

- 校门、门卫区、校名石、主入口道路；
- 主教学楼、北教学楼、南教学楼及其连廊；
- 主教学楼左侧相连的独栋厕所；
- 办公楼、实验楼、科学馆、图书馆；
- 体育馆完整外观与主要室内空间；
- 体育馆后方、跑道边的音乐教室；
- 食堂及主要就餐空间；
- 田径场、主席台、国旗区、沙坑、风雨跑道；
- **3×2 六片篮球场，以及与其平行且紧贴的相邻跑道**；
- **相邻跑道图面左侧的体育辅助用房组**：健身／锻炼空间、体育教师办公室、运动器材／器械空间；
- 游泳池及其左侧厕所；
- 宿舍及其他有充分资料的校园建筑；
- 围墙、道路、台阶、坡道、排水、栏杆、树池、路灯、公告栏等环境构件；
- 具有时代辨识度的门窗、空调外机、管线、灯具、桌椅、黑板、标牌等细节。

资料不足的室内空间可以暂时关闭，但不得用无依据的“标准教室 / 标准厕所 / 标准办公室 / 标准体育器材室”冒充真实复原。

## 4.3 模型精度标准

### A. 空间精度

- 全项目统一真实单位，建议 `1 unit = 1 m`；
- 每栋建筑记录尺寸来源：实测、公开图纸、照片推算或校友确认；
- 不对缺失尺寸制造伪精确数值；
- 建筑位置、高差、入口、楼梯、连廊和厕所连接优先于表面装饰；
- **“紧贴／直接相邻”属于拓扑事实，不得因为暂时缺少米制尺寸而退化成“差不多靠近”。**

### B. 建筑形体精度

关键建筑需要通过至少三类视角校核：正／斜前方、侧面或背面、校园步行视角或高位关系视角。不能依靠一个“最像照片”的固定机位掩盖错误结构。

### C. 近景细节

对于校门、体育馆、主教学楼入口、教室、走廊、食堂以及运动区辅助建筑等高频记忆场景：

- 门窗有真实进深；
- 柱、雨棚、窗台、女儿墙、栏杆、台阶不使用贴片假结构替代；
- 标识、题字和校徽位置按照片校准；
- 材质应表现瓷砖、混凝土、旧墙漆、玻璃、金属、木材等实际表面差异；
- 重复构件允许实例化，但不能因此丢失建筑特征。

## 4.4 体育馆专项

体育馆列为 M1 的重点资产，继续从当前工作模型提升到可近距离观察的建筑级模型。

必须进一步完善：两侧折面壳体厚度与交接、中央立面层级、五环所在体块比例、内凹窗带及玻璃进深、首层平台与入口、左侧外梯、背面体量、室内外开口对应以及近景材质节点。

验收必须提供同一模型至少 6 个固定机位截图，与照片逐一对照。

## 4.5 运动区专项

运动区是本轮新增的 M1 高优先级校核对象。

### 几何关系

- 六片篮球场作为一个整体保持 3×2；
- 篮球场整体长轴与相邻跑道平行；
- 篮球场与相邻跑道边界直接贴合；
- 跑道图面左侧布置体育辅助用房组；
- 音乐教室仍在跑道边和体育馆后方，但保持独立对象；
- 泳池左侧厕所位置不能因运动区重排而漂移。

### 体育辅助用房建模

第一轮精模至少需要把这组房间从“泛化附属楼”提升为可辨认的功能空间。已知功能：

- 健身／锻炼及器材使用空间；
- 体育教师办公室；
- 运动器械／体育器材存放空间。

如果现阶段不能确认具体分间，模型可先保持一个或多个真实外轮廓体块，但必须在元数据中挂出三个功能区和 `pending` 分隔，不能把三者直接抹成一个无定义房间。

### 运动区验收机位

至少保存：

1. 能同时看见篮球场和相邻跑道紧贴关系的高位机位；
2. 沿跑道纵向观察六片篮球场平行关系的机位；
3. 从篮球场方向看跑道图面左侧体育辅助用房的机位；
4. 从体育馆后方验证音乐教室、跑道和辅助用房相互独立的机位。

## 4.6 环境还原

“像学校”不能只靠建筑。M1 必须同步建立主要树木、校园边界与可见城市轮廓、电线灯杆与宣传栏、运动场和跑道真实铺装线位，以及教室／走廊／食堂／体育空间中的日常陈设。

## 4.7 M1 技术目标

M1 的技术开发只服务于“看得准、走得动、便于校核”，不提前扩张玩法系统。

需要：稳定 Web 3D 加载、第一人称或自由漫游、固定对照机位、区域分块／LOD／实例化、稳定设施 ID、白天灯光、一键校核截图和常见电脑浏览器持续运行。

可以暂缓：复杂交互、怪物 AI、谜题、任务、背包、剧情状态机、战斗与商业化 UI。

## 4.8 M1 验收标准

- 校园室外空间可连续漫游，不出现明显空洞或临时盒子；
- 关键建筑全部完成多机位照片校核；
- 校友能凭空间关系辨认路线，而不依赖 UI 地图；
- 体育馆、校门、主教学楼、运动区等核心地标达到近景展示质量；
- 运动区满足 `data/spatial-constraints.json` 中所有 `alumni_confirmed` 拓扑约束；
- 已开放室内从室外进入时拓扑、楼层和开口一致；
- 所有不确定结构在资产元数据中保留证据等级；
- 历史基底不被现代覆盖层或夜间效果污染。

# 5. M2：全校园夜间中式梦核设计

M2 在 M1 基础上进行。**M2 的重点是夜间世界的美术、空间与氛围设计，不是具体玩法设计。**

白天保持可信、正常、可怀旧的现代返校感；夜晚让同一所学校进入循环梦境中的中式梦核状态。

## 5.1 核心原则

- 夜晚必须仍然能被校友认出是雅礼，而不是换成泛用恐怖学校；
- 恐怖来自熟悉空间的不正常，不依赖血迹、尸体或商业恐怖模板；
- 保留中国高中独有的视觉和声音记忆；
- 梦核空间异常必须建立为覆盖层，能够随时恢复 M1 的真实校园基底；
- 夜间不依照现实钟表自动到来，具体触发规则留到后续游戏设计阶段。

## 5.2 M2 交付

- 全校园夜间视觉圣经；
- M1 所有核心区域的可浏览夜间版本；
- 校门、教学楼、厕所、体育馆、音乐教室、运动区、体育辅助用房、泳池、食堂、图书馆、实验／科学区域、教室、楼梯、走廊和宿舍公共区的白夜成对机位；
- 环境声音氛围原型，不提前设计谜题机制。

## 5.3 梦核空间语言

可以实验但必须可逆的异常包括：路段长度轻微错位、远端灯光多一组、窗后出现不属于当前楼层的灯、广播声源方向错位、公告重复以及大空间尺度感异常。

这些仅作为视觉／空间研究方向；是否成为玩法规则，留待 M3 以后决定。

## 5.4 M2 验收标准

- 所有核心场景都有白天／夜晚成对截图；
- 夜间仍能凭建筑轮廓识别具体校园位置；
- 验收图来自实际 Web 3D 场景，不用生成式图片假装实机；
- 夜间变体不修改 M1 校准过的基底网格和设施坐标；
- 至少邀请一组校友只看场景、不讲剧情，确认“既熟悉又不安”的方向成立；
- M2 完成后才决定哪些空间异常转化为正式游戏机制。

# 6. M3 以后：互动与游戏内容（暂缓详细设计）

M3 以后才开始把校园复原和夜间梦核转化为完整游戏。现阶段只保留高层级目标：基础行走与查看、简单物件交互、白天／夜晚条件式切换、循环梦境状态、剧情／幽魂／怪物／谜题以及校庆浏览器发行。

M3 的设计必须服从 M1/M2 已完成的校园资产，不得为了关卡便利随意挪门、改楼梯、堵道路或改变真实建筑比例。

---

## 7. 近期工作排序

### P0：校园空间与证据

- 完成修订总平面继续校核；
- **优先修正篮球场—跑道紧贴关系，并恢复跑道图面左侧体育辅助用房组**；
- 获取更多 2006—2010 校园照片；
- 为每栋楼建立证据卡；
- 校核厕所、音乐教室、体育辅助用房、体育馆后场、泳池周边等剩余模糊区域；
- 收集可用于尺度推算的门、窗、跑道、球场等已知尺寸参照。

### P1：全校园精模

- 将当前工作模型逐栋升级；
- 优先体育馆、校门、主教学楼、运动区；
- 运动区先把拓扑关系改正确，再进入材质和小构件细化；
- 随后完成食堂、教学楼群、实验／科学／图书区域、宿舍；
- 统一树木、铺装、围墙、道路、路灯与生活设施；
- 建立关键室内。

### P2：现代白天状态

根据可靠现代照片建立覆盖层；不覆盖历史基底；建立自然日光与普通校园生活感；制作全部主要区域的现代白天对照截图。

### P3：中式梦核夜晚

等 M1 达到完整度后再系统展开；同一模型制作夜间灯光、材质、声音和空间变体；建立全校园夜间视觉圣经与对照机位。

### P4：具体游戏设计

暂缓。M1 与 M2 未通过验收前，不把主要时间投入谜题数量、怪物行为树、关卡时长或结局分支。

## 8. 面向校庆的发布标准

本项目不是商业产品，因此发布标准强调校友辨识度和回忆价值、浏览器打开即可体验、无需账号和商业后端、资料来源与摄影权利尽可能清楚、对真实师生保持尊重，并保证即使后续游戏内容尚未完成，M1 校园漫游版本身也能作为独立校庆作品发布。

**项目成功的第一判据不是“做成一个恐怖游戏”，而是“把那所学校重新做出来”。**
