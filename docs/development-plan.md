# 开发计划与验收门槛 v0.3

项目：`ziyuuu/return-old-school`。版本日期：2026-09-09。

## 1. 目标与范围

目标是一个以雅礼东塘校园为历史空间参照、具有现代白天调查与梦核夜晚解谜的电脑浏览器游戏。长期目标为可证据化的真实尺度复原；当前阶段是资料约束的形体工作模型，不能对外标称已完成全校 1:1。

近期唯一产品门槛：**一条能让玩家先喜欢校园、再害怕熟悉空间、最后理解一个幽魂诉求的完整可玩路线。** 不先铺满六章半成品，不先建全校每一个室内。

首条切片使用 01 校门、07 办公楼／医务室、15 主楼与教室、25 左侧厕所连廊及其间公共路径。目标 20—30 分钟，包含三证据任意顺序、一次条件转换、一个有明确规则的威胁、一次可恢复误判、一个心结与存档。体育馆、运动区同时作为独立美术校核支线，不挡住第一夜的逻辑开发。

全作内容目标 3—5 小时／六夜；这是范围假设，不是当前可玩时长或交付承诺。全部 26 个既有设施编号有昼夜作用；不等于所有房间或居民住宅均可进入。

## 3. 工作区组织

- `viewer/`：沿用原生 WebGL2 的建筑证据查看器，零外部运行资产。
- `src/dream-state.js`：纯剧情 reducer，不把状态藏在 mesh 或 DOM 里。
- `data/facilities.json`：设施 ID、两时段用途、工作坐标与证据边界。
- `docs/`：剧本、开发计划、美术合同、空间修改和研究引用；文档为源文件。
- `tests/`：状态与空间约束回归；`qa/` 为运行记录和实际浏览器截图。
- `tools/`：原图增量修改、自动截图、PDF 构建与可复现源快照。
- `artifacts/`：从源文档、矢量原图修改版、实际截图构建的评审 PDF。

所有工作进入用户指定仓库。原代码查看器不悄悄改成别的技术栈。正式游戏若迁移到 Vanilla Three.js＋TypeScript＋Vite＋Rapier，必须在 M1 做一次书面决策，锁定版本，先证明同一资产、机位与状态能够无退化迁移，再逐步替换。禁止把重写渲染器当作每次改图的前置任务。

## 4. 分阶段交付与依赖

下表以 **1 名开发＋1 名环境美术／技术美术，用户每周参与历史校核，并有叙事与音频兼职支持**为估算前提。阶段可并行的部分已说明，整体约 20—30 个日历周形成有限室内范围的六夜版本；资料不足或单人制作需重新估算，不以此作为固定报价或日期承诺。

| 阶段 | 估算 | 核心输出 | 进入下一阶段的条件 |
|---|---|---|---|
| M0 证据与空间锁定 | 1—2 周 | 目标年代、U8—U11 校核、建筑清单、首路线粗模 | 左厕连接、门位置、高差与路线可解释；未知项明确挂牌 |
| M1 工程骨架 | 2—3 周 | 运行栈决策、角色控制、统一交互、存档、区域载入 | 上下楼梯与开门稳定；状态不依赖画面帧率；转场能回滚 |
| M2 第一夜完整切片 | 4—6 周 | 白天三线索、左厕遭遇、怪物规则、回到白天、基础音频 | 非校友可理解解法；错误选择可恢复；无阻断；首次形成性试玩 |
| M3 核心建筑与视觉提升 | 3—5 周，可与 M2 部分并行 | 体育馆内外统一、校门与主楼精模、昼夜材质、运动区 | 同模型多视角校核、节点质量、真实尺寸记录、预算不过线 |
| M4 六夜内容扩展 | 6—10 周 | 全设施用途落地、五个新章节、分支结局、音频事件 | 每章与前章产生状态回响；所有主线入口有安全锚点 |
| M5 Beta／发布准备 | 3—4 周 | 兼容测试、无障碍、性能优化、来源与授权复核 | 下述发布门槛全部满足；未授权资产移除 |

关键依赖：第一夜不等全校精细建模；怪物动作与声源设计必须在 M2 内做，不留到“最后加恐怖”。体育馆外形核验和第一夜逻辑可以并行；后续六夜必须等第一夜证明设计能成立。

## 5. 近期工作包

### P0／阻断级

**SP-01 厕所连接校核。** 用户确认连接哪侧门、哪些楼层及能否直通；美术建立真实洞口；开发做门和台阶碰撞。验收：玩家从主楼左侧走入独栋厕所在所有相机下拓扑一致，不穿墙，不由美术临时平移解决。

**SP-02 音乐室与跑道定位。** 保留馆后与跑道旁两项约束，补影像或口述草图，确认门朝向。验收：白天从跑道听音再到教室的路线有可核实地标，不依赖任意“背后传送”。

**SYS-01 一套统一动作接口。** `inspect / read / take / use / open / close / compare / return`，带距离、遮挡、条件、反馈和存档键。验收：无法隔墙取物，同一对象不重复发奖励，已开门刷新后状态正确。

**SYS-02 原子白夜切换。** preload、碰撞锚点检查、存档、过渡提交、失败回退。验收：资源失败、失焦、连续交互、错误 token、刷新发生在任一阶段都无进度损坏；等待不会入夜。

**NAR-01 第一夜灰盒。** 按剧本 D1—N6 搭建，不增加新谜题。验收：六种取证顺序都能完成，错误替答至少一次可挽回，声音线索有视觉等价。

### P1／质量级

**ART-01 体育馆细部与内外统一。** 先校核折面、壳厚、退窗、平台、外梯，再做接缝；补材质 ID、门轴、碰撞代理与 LOD。验收：正侧背三向无假墙，室内开口对得上外壳，未确认构造有注释。

**AI-01 借声者遭遇。** 明確 `dormant / warning / stalk / intercept / reset` 五态，障碍、视线与声音规则可重复测试。验收：第一次错误不立即死亡；不得瞬移到镜头正前方；不能通过站上小物件永久失去威胁。

**AUD-01 校园生活声与夜间错位。** 门轴、吊扇、球、脚步、普通广播，逐个登记来源和循环边界。验收：自动播放受阻有明确“进入校园”交互恢复；关背景音乐仍能解谜；字幕标注关键声音。

**QA-01 形成性试玩。** 5 名非校友＋3 名校友，记录困惑与紧张而非只问“吓不吓人”。验收：至少能解释关键选择的因果；任何同类三次无理解失败需修改提示。

### P2／扩展级

其余五夜分别建独立工作包，先有 dayFacts、entryTrigger、nightThreat、resolutionSteps、returnDelta 和 facilityIds，再创建模型。终局只检查主线五个解结，不以可选收藏品百分比锁住出口。支线回忆只改变语音、寄存物与结尾细节。

## 6. 资产与精度流程

每个资产维护三层：展示几何、碰撞代理、交互锚点。门轴在合页，窗框有真实进深，楼梯按实际通行尺寸；不把多边形数量当精度。关键建筑需要照片相机匹配、至少一个可靠尺度参照和可解释的缺失面假设。

优先级：校园轮廓与连通＞地标轮廓＞门窗开间和高差＞可近看的节点＞装饰细节。未知尺寸以范围记录，不用常见学校尺寸冒充实测值。现代覆盖层与历史基底分别评审，夜间变化不得写回基底。

## 7. 性能与体验预算

基准平台先确定为电脑键鼠、1080p，选择一台真实集显机器和一台独显机器登记型号。目标帧率 60fps，低配置可降至稳定 30fps；在未实际采集之前只能标“目标”。GitHub Actions SwiftShader 截图用于正确性，不是性能认证。

初始工程预算：首场景压缩传输不超过约 20MB、首可操作状态在指定网络下 10 秒内、单活跃区域不超过约 250 个 draw calls、阴影灯限定范围、重复桌椅窗框实例化。阈值可在 M1 实测后重订，并记录修改原因。无贴图不意味着无内存成本；汉字几何与细接缝仍可能产生大量三角形。

## 8. 测试矩阵

| 测试域 | 必测案例 | 合格标准 |
|---|---|---|
| 空间 | 左厕所／池左厕所／六片平行球场／馆后音乐室 | 数据、地图、模型三方一致；不存在左右镜像 |
| 转换 | 缺证据、重复触发、提交失败、刷新、中途暂停 | 不穿墙、不丢证据、不由时间自动变夜 |
| 存档 | 损坏 JSON、版本不符、localStorage 不可用 | 有可见恢复说明，不能空白崩溃 |
| 解谜 | 错序、先拿后读、返回旧区、失败重进 | 无软锁，不消耗唯一关键物品 |
| 恐怖 | 玩家不按预设顺序、关声音、低运动模式 | 规则仍可理解，威胁不靠不公平瞬杀 |
| 浏览器 | Chromium、Firefox、Safari 的目标版本 | 记录真实版本；至少一套跨浏览器实测后再标支持 |
| 展示 | 1600×1000、1080p、窄屏查看 | HUD 不遮交互，查看器可降级；手机游玩另行立项 |
| 权利 | 照片、音乐、字体、姓名、标识 | 有来源与用途记录，未知授权不得随公开包发布 |

本轮实际 Node 检查为 16 项；浏览器项以执行报告为准。后续 CI 应运行同一源码与固定机位，不能将预先生成的 PNG 当渲染通过。

## 9. 协作与变更控制

主分支保存可读文档与已通过自动验证的源代码。每次改图提交：用户校正编号、受影响设施、前后对照、剩余不确定项。每次改剧本同时更新状态图与道具依赖；若只是文字更漂亮而动作不变，不算解谜改进。

推荐分支 `feature/left-annex-slice`、`art/gym-shell`、`narrative/night-01`，通过 PR 评审后合并。空仓初始化阶段已直接提交本轮材料，不擅自改仓库访问权限、开启付费服务或发布未经批准的游戏商城页。

首个评审次序：核左侧连廊→第一夜白天日常→第一次门槛转换→借声者规则→解结回程。对剧本恐怖程度的最终判断，交给实际游玩，而不是海报、文案或渲染截图。
