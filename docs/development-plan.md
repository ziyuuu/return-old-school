# 开发计划与验收门槛 v0.7

日期：2026-09-09。项目：`ziyuuu/return-old-school`。

本项目为校庆和同学回忆服务，不按商业游戏开发。**校园真实复原 > 模型精度与环境完整度 > 白天表现 > 夜间中式梦核 > 玩法。**

本次修订只处理资料、二维图、来源核验与推定交接，不创建三维模型、不设计谜题或怪物AI。

## M0：资料与推定工作基线

已有手册、设施编号、公开图源和原总图局部订正继续使用，不再重画一套校园。

### 本轮确认

- 六片篮球场3×2，与相邻直跑道平行、紧贴；跑道在篮球场和体育辅助用房之间。
- 体育辅助用房低矮单层；健身/锻炼、体育办公室、器材是功能，不等于三栋房。
- 音乐楼四层独栋，体育馆后、跑道旁。
- 主教学楼左侧独栋厕所每层连接，门朝教学楼；两张草图按同一典型层关系处理。
- 池畔厕所位于泳池左侧；不套主楼厕所的T形内部关系。

草图中的直跑道项目绑定05，08保留为田径环道；这个绑定不是历史官方编号。

### 推定权限

优先检索雅礼原始资料，找不到时按用户授权参考公开同类学校和时代标准，或选取标明H的保守工作值。数据必须区分A校友确认、P实拍、R参照与H推定。不同年份不相互覆盖。

缺少现场测量不再是继续研究的无限阻断项；没有实测的字段仍为空，工作值另存。全校真实米制控制网、全部隐藏面和全部楼层图并未因此完成。M0当前名称为“资料与推定工作基线”，不能写成“全校实测1:1已通过”。

M0交接应包含：原图版本和局部修改、设施与草图绑定、来源、实际照片、二维构件图、12项工作参数、问题状态及可回退说明。已确认事实不能在旧表里退回“等待用户回忆”。

## M1：全场景深度还原与模型精度优化

**M1核心是整个校园，不是第一夜可玩切片。** 本轮没有启动M1三维制作。

### 范围

校门与门卫、校名石；教学楼群、主要教室/走廊/楼梯及逐层相连厕所；办公、实验、科学和图书区域；体育馆内外；四层音乐楼；低矮体育辅助用房；田径场、主席台、旗台、沙坑、风雨跑道、六片篮球场、泳池和池厕；食堂、小卖部线索、宿舍公共区域；道路高差、围墙、树木、树池、栏杆、路灯、排水、管线、标牌、桌椅和其他校园物件。

资料缺失可用H填入形体方案，但不能编造正式楼名、真实人物信息或私人住宅内部。全场景登记不等于所有房间都已有真实照片。

### 精度要求

1. 稳定设施ID；统一单位，但将未验证工作尺寸与实测分开。
2. 保持已确认方位和连接，不为方便建模移动建筑。
3. 每个关键建筑提供正面、斜前、侧后与行走视角；缺失视角不能机械镜像。
4. 门窗进深、壳体厚度、台阶、平台、栏杆和连接洞口是真几何要求，不只靠单张照片机位遮错。
5. 已开放室内应与外壳开口和楼层对齐；厕所对应每个主楼层连接。
6. 绿化以已见株位和冠层遮挡为骨架，缺失树种、胸径和枝形另标H/U。
7. 历史基底、现代白天和夜间覆盖层分开，图像年代不混用。

### 体育馆重点

保留旧馆折面壳体、中央面板、内凹窗带、入口平台、外梯和内外开口关系。背面本轮仍无新清晰独立照片，允许以H10保守补足；不得把2023新馆方案或正门镜像当成旧馆背面事实。

### 工程与验收

技术仅服务于看得准、走得动和可校核：浏览器加载、自由漫游、固定机位、截图、分区/LOD/实例化。不给谜题、任务、背包或怪物排优先工作。

全校园主要室外连贯、核心建筑近景可信、校友可凭记忆认路、照片和假设可回溯，才算M1达到交付质量。性能目标在真实目标电脑上测试，不以自动化截图代替硬件性能测评。

M1校园漫游本身可以独立用于校庆，不必等待完整剧情。

## M2：全校园夜间中式梦核

在M1校园上增加可逆的灯光、材料、声音、空气感和空间异常覆盖层。重点是“这里依然是雅礼，但熟悉环境不正常”，不是通用废校模板或简单调暗。

每个已开放白天区域都建立相应夜间版本；同机位昼夜对照。教室、厕所、音乐楼、体育辅助房、体育馆、食堂、运动区、图书馆和道路绿化均应覆盖。夜层不得写回历史基底。

当前不制定具体谜题、追逐、怪物AI或章节时长。白夜转换不按现实时间自然轮换的高层方向保留；具体触发另阶段设计。

## M3以后：互动与游戏内容

根据完成的校园和夜间空间决定互动、循环梦境、幽魂、怪物与叙事。不得为了玩法方便改变已校准的真实建筑关系。
