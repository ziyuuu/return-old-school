# M1.0 空间骨架与坐标基线

版本 M1.0.0，资料基底 v0.7；2026-09-09。为校庆校园还原服务，本阶段不做玩法、夜景或精细建筑。

## 当前交付与边界

已建立可执行 Three.js 场景、独立布局数据、逐项足迹、结构连接、机位与校核脚本。28项是语义设施：27项有工作定位，22小店线索尚无可靠落点，保留U，不把它放在原点或虚构店面。12是11食堂内部下层功能对象，不是独立建筑。20是周边住宅区域，不采集私人内部。

M0按“资料与推定基线”关闭，不按“全校测绘1:1验证”关闭。M1.0本轮是**实现并提交校核**，不等于校友已经验收，不等于M1整体完成。浏览器验证以生成的qa/m10/browser-report.json实际结果为准。

## 坐标合同

- 原点：01主校门通道中心地面，(0,0,0)。+X为原图图面右，+Y向上，+Z为原图向下/入校方向。
- 1场景单位=1工作米；没有GNSS/大地坐标，不声明EPSG。
- Three到Blender：(x,y,z) → (x,-z,y)，逆变换(x,y,z) → (x,z,-y)。保持右手系，禁止凭视觉镜像。
- **所有世界坐标和尺寸仍是H**。事实层只确认楼层数、相邻、左右、连接等，不能伪造一个confirmedTransform。
- 不把球场符号m/px套用全校园。各楼尺寸用M0的H值；其余逐项填入明确的M1工作包络，位置按原图关系人工安排。
- 1447×1024图面框只用于追溯原位置，不参与全图线性缩放。依据摘要在每个对象的sourceDiagram/evidence中。
- 高差未标定，本阶段暂用H平基准。未来楼层标高及台地只修改指定参数，不把临时平地当校园事实。

## 关键拓扑

05直跑道和06六片球场沿Z平行，共边x=-65；六片净场按15×28工作矩形，外围3m、间距2m为新增H，不复刻未经核实的三分线。28在05左侧，24/26/04同处条形组团的一端。28单层、24四层独栋来自校友，层高分别3.3/3.8米属于H。

25在15左侧，当前主楼按4层H生成4条连接，门朝+X的主楼。主楼前廊和厕所中部在几何上留出连接空间，不让桥接到封死的体块。主楼若调整层数，应同步调整桥层，不把“四层厕所”标为独立证据。

10在08左侧；23在14附近；27在01右侧。布局输入、足迹导出和渲染共用数据，不另手工维护PDF坐标。编辑data/m10/layout-input.json后运行python tools/m10/generate-layout.py，导出文件不可手动修改。

## 建筑表示等级

本轮是占地/体量/楼面基准，不是校门或体育馆精模。体育馆只提供H10的30×36×15体量和简化折面；中央面板、屋盖、窗框、外梯及内场仍留M1.2。各楼水平线是楼层基准，不是实际窗带。没有随机添加树木、器材或生活物件来掩盖精度。

展示颜色来自Canvas Ramp LUT，阴影乘查表坐标，单方向光、无后期。色彩用于体量校核，不是已经完成的历史材质。

## 查看器

全校鸟瞰、正投影总图、运动区、主楼连廊、体育馆及校门原点共6个机位。可点体块查数据、显示网格/轮廓/路线、导出布局和WebGL画布。

“自由校核”是允许穿体的相机，非物理角色；“路线巡览”沿已检查的图边进行低空播放，不是完整步行系统。路线检查使用体块代理与0.6m工作余量，不能替代后续实际碰撞验收。

## 回归与验收

30项自动化测试覆盖ID、共边、六片球场、单层/四层、逐层连接、父子空间、路线及坐标转换，并用故意插入间隙、删桥、改层数和堵路验证检查会失败。它们验证内部一致性，不证明历史真实性。

浏览器检查以实际qa/m10/browser-report.json为准；截图必须来自Three.js运行。软件渲染测试不作目标电脑帧率承诺。

M1.0校友评审重点：总体轴距是否明显失真、入口与路线是否合理、运动组团是否与记忆一致。新证据到来更换H参数并运行回归。22未定位、高差暂平、部分身份未定均明示为残余风险。

## 本地运行

```bash
python tools/m10/generate-layout.py
cd apps/campus
npm ci
npm test
npm run dev
```

首次发布CI会生成并提交package-lock.json。构建使用npm run build；独立单文件使用npm run standalone。若源码快照尚没有lockfile，只在首次运行npm install生成，之后使用npm ci。
