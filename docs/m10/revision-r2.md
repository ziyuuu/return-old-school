## 事实与H工作方案的界限

24的独立体块不等于不连通，本轮明确连接03，不与28合并。25仍在15左侧，草图注册为相向端墙中线接入，不将厕所搬到教学楼背后；首层平接与地面穿行十字交叉、上层桥下留净空是具体构造工作方案。

| 参数 | 原工作值 | 本轮工作值 | 限制 |
|---|---|---|---|
| 体育馆03包络 | 30×36m | 42×42m，高仍15m | A要求体量更大，准确尺寸H |
| 旧厕26占地 | 6×4.5m | 4.2×3m，高3m | A要求更小及圈注定位，配准与尺寸H |
| 风雨跑道顶棚 | 无 | 净高4.1m、最大柱距8m | 有棚A；棚型高度柱距H，不扩展成整栋训练楼 |
| 03—24连接 | 无 | 2.4m宽开敞带棚接驳、净高3.4m | 连接存在A；连接楼层和构造H |
| 后缘橡胶直段 | 无独立直段 | 92×7m，23在右端 | 位置关系A；长度、宽度、线位H |
| 02侧门与小路 | 入口旁未核标记 | 入口分支沿操场右侧至新工作端点 | 路线关系A；门精确落点、弯折、宽度H |

## 实际代码与运行

布局输入`data/m10/layout-input.json`生成`campus-layout.json`，主要占地导出为`footprints.json/csv`，次级结构和路线导出为`site-features.json`。

`revision-core.mjs`提供物理部件和检查，`revision-scene.ts`创建实际顶棚、建筑开口、折面屋盖、连桥和橡胶直段。原`main.ts`和`layout-core.mjs`已经接入；没有只增加文档而保留旧场景。

`tools/m10/repair-r2.py`与`.github/m10-r2.patch`记录一次性迁移；通过CI后，实际修改后的源码已提交回main。后续在已修复源码上不需要手工重做迁移。

```bash
python tools/m10/generate-layout.py
cd apps/campus
npm ci
npm test
npm run build
npm run standalone
```

查看器新增球场看馆、棚下、后缘跑道、图书馆通路、两楼间穿行和侧门小路机位。设施面板的“顶棚/接驳屋盖”只切换可见性，不移动设施。

M1.0仍为工作体块：完整人物碰撞、所有楼层楼梯、精细内装和准确隐藏立面留待后续M1。不增加玩法或夜景，不把路线巡览称为完整游戏。
